# EduMind 高校智慧教学平台

EduMind 把课程、教学班和课堂活动连在一起。《随堂三问》是它的授课模块：教师讲完一个知识点，发出基础理解、误区辨别和迁移应用三题，观察本班真实作答，补讲后再用变式复测。示例来自大一 Python 程序设计课“递归出口与调用栈”。作品对应 TRAE AI 校园黑客松学习教育赛道「辅助教师教学」。

[在线演示](https://biology-get-genesis-third.trycloudflare.com/) · [作品简介、路演稿与演示脚本](./参赛材料.md) · [第三方软件声明](./THIRD_PARTY_NOTICES.txt)

公开地址使用临时 HTTPS 隧道，演示电脑、Go 服务和隧道需保持运行。扫码手机可直接访问该 HTTPS 地址，无需连讲台电脑的 Wi-Fi。

## 开课与课堂复测

本地需要 Go 1.20 或更新版本，从项目根目录执行 `go run .`，打开 [本机门户](http://localhost:8787)。发布资源随源码提供，无需安装 Node 或提供模型密钥即可走完课堂主流程。

1. 教师登录后创建课程与教学班，在课程里点「开始授课」，展示本堂课的二维码。学生用各自账号进入同一入口，跟随教师翻页、点选课件内容提问，在教师开启签到时提交到场记录。
2. 教师讲完一个知识点，在该授课页点「用本页编排三问」。核对题目、正确答案、解析与错项提示，选择是否开放学生反馈，再发布。首次三问在当前课堂生效，已加入的手机会自动收到，课堂码、已加入名单和签到记录继续沿用。
3. 让三位学生从各自账号提交。例如分别选择 B/A/D、B/A/D、B/C/D。教师可看到第二题 A「0」集中出现，并用调用栈逐步讲解，说明出口返回值如何回到尚未完成的各层。
4. 推送 power(3) 变式，学生从原页面回答。大屏对照完成变式的同一批学生在两轮中各有多少人选对。学生回工作台可继续查看个人错题与复习进度。

如果本堂课已经发布三问，再生成下一组三问会新建课堂活动并生成新的二维码。请展示新入口，让学生加入下一活动；原活动保留原有作答与签到记录。

## 教师与学生工作台

| 入口 | 可操作内容 |
| --- | --- |
| 课程与班级 | 教师创建教学班，分享邀请码，在同一课程下管理课堂。学生加入课程并访问课堂记录。新课堂按登录账号与课堂绑定参与者。 |
| 课件与副驾驶 | 教师导入 PPTX（单文件最多 12 MiB），或手工添加授课页，选择当前页同步给学生。学生可点选文字、公式、代码或图片提问，并决定是否主动分享疑问。教师看到按页和类别汇总的提问，私下提问不会自动展示给全班。 |
| 教学分析与复习 | 教师能从实际提交看选项分布、共性误区和复测结果。学生端按已开放反馈的实际答卷生成错题与复习任务，可保存完成状态。 |
| 知识图谱与虚拟实验室 | Python 示例给出函数调用、出口、调用栈等概念的先修关系，可查看关联课堂与学习记录；其他课程按已发布主题建立节点。数据结构实验可压栈、出栈并观察顺序。 |
| 课堂签到 | 教师在某堂课的管理页开启签到。学生可用实时摄像头提交现场材料，或选择人工到场核验。教师私下按状态审核，学生可查看本人的结果与备注。 |

课件副驾驶对 PPTX 做结构化提取，保留可读文本、代码、公式及支持的图片。复杂版式、动画、视频与 Office 渲染效果不作还原。课件图片解析可配置 `AI_VISION_MODEL`；缺少模型时使用教师课件的图注。平台账号由用户自行注册，学校教务 SSO、实名学籍校验和校园排课系统对接未接入。

## 签到与授权

教师主动选择 2、5 或 10 分钟，系统为本轮生成六位现场码和随机手势。教师将码展示在教室现场。学生在自己的登录会话中选择实时拍照或人工签到。每个学生账户在同一课堂同一轮只登记一次，截止后停止接收新的申请。同一课最多可开 12 轮。

照片路径使用单独的学生授权。点击“开启摄像头”后浏览器才申请视频权限，不采集音频；学生可以预览、重拍或改用人工。教师页面只显示记录汇总，退出投屏并进入私下审核后才可单独打开照片。查看接口校验任课教师身份、管理令牌与本轮发起者。图像保存于 `DATA_DIR/attendance/<课堂码>/photos`，和 JSON 状态分开，绝对有效期 10 分钟；审核完立即删除，过期立即禁止读取。进程运行时每 30 秒清除到期文件，停机期间到期的照片在下次启动清理。账号与审核状态存于课堂专属目录，学生仅可查看本人的签到记录。

默认由任课教师人工核验。可选视觉服务需要同时配置 `ATTENDANCE_VISION_BASE_URL`、`ATTENDANCE_VISION_API_KEY`、`ATTENDANCE_VISION_MODEL`，远程地址要求 HTTPS。只有教师开本轮时允许、学生另行同意该服务、教师在私下审核中主动点击发送，Go 才向界面标出的服务发送当前照片。请根据现场用途选择有权使用、图像处理条款适合的供应商。服务端对送出的图片移除 JPEG 元数据。外部供应商的保存和删除受其自身条款约束。

模型需返回前景人物、板前另一人、课堂板面、随机手势、实际读出的现场码和联合置信度。全部要素匹配且模型自报置信度至少 0.90 时，界面提示教师核对场景。缺项、低置信或上游失败均进入人工判断。模型自报分值不能视为真实准确率；未取得现场标注样本测算识别性能。账号会话能证明操作来自本次登录，影像中的人是否就是该学生和任课教师仍由任课教师确认。此演示不建立人脸模板，也未实现自动生物身份认证、活体防伪或无人审核的到场判定。

局域网访问用实际可达的 `PUBLIC_BASE_URL`（例如 `http://192.168.1.20:8787`）。手机摄像头通常需要 HTTPS；HTTP 局域网仍可使用人工签到。正式演示前用场馆网络和物理手机复核一次。

## 单服务部署

**Go 可执行文件。** 以下命令构建的文件内含师生界面和二维码资源，可单独拷到同架构的系统运行。设置 `DATA_DIR` 指向本项目的独立持久目录。启动时如工作目录下有 `web/index.html`，服务优先读取该份前端，方便现场调整。

```bash
go build -trimpath -o sanwen .
DATA_DIR=./data/rooms ./sanwen
```

**容器。** 将本仓库作为构建上下文。镜像只运行一个无特权 Go 进程，一个命名卷保留历次课堂。示例命令适用于本机和局域网演示。

```bash
docker build -t suitang-sanwen .
docker run --name suitang-sanwen -p 8787:8787 \
  -v suitang-sanwen-data:/data \
  -e PUBLIC_BASE_URL=http://192.168.1.20:8787 \
  suitang-sanwen
```

**评委公网入口。** 在支持 Go 进程或 Docker 的主机部署一个实例。将公网 HTTPS 域名反代到该进程，设置 `PUBLIC_BASE_URL` 为实际访问源站（例如 `https://class.example.edu`），将专属持久卷挂到 `DATA_DIR`。根路径 `/` 为教师入口，`/healthz` 为 HTTP 健康检查。以平台动态分配的 `PORT` 监听时无需设置 `ADDR`。完成部署后，用校外网络打开教师页、建课，用手机扫码并提交一份答案，确认大屏出现该提交再向评委发链接。域名示例仅作配置说明。

| 环境变量 | 作用 |
| --- | --- |
| `ADDR`、`PORT` | `ADDR` 优先，可设为 `127.0.0.1:8787` 供同机反向代理使用。默认监听所有网卡的 `PORT`，端口默认 8787。 |
| `PUBLIC_BASE_URL` | 从手机及评委网络可访问的 HTTP(S) 根地址。HTTPS 代理、容器和多网卡部署应显式设置。 |
| `DATA_DIR` | 默认 `data/rooms`，容器默认 `/data/rooms`。一个服务实例独占一个目录。 |
| `WEB_DIR` | 可选，用指定目录覆盖内置静态页面。 |
| `AI_API_KEY`、`AI_MODEL` | 由服务端读取。使用主持团队有权调用的模型及密钥。 |
| `AI_BASE_URL` | 兼容 Chat Completions 的上游 API 根地址，默认 `https://api.openai.com/v1`，服务自动追加 `/chat/completions`。 |

AI 出题只向模型发送课程、年级、知识点、录入的讲义及出题要求。未配置模型、上游超时或输出无效时，系统返回明确标注的高校 Python 预置范例，并保留该范例自己的讲义、课程和知识点。教师审核材料与题目后再发布。答疑以本课堂的可用资料为依据，学生可以核对引用片段。程序按教师确认的答案计分。

## 统计与数据

- 每个课堂获得独立六位加入码和教师管理令牌。新课堂使用师生登录会话做角色校验，学生在同一课堂的答卷绑定账号；刷新、换浏览器后登录同一账号以及重发相同答卷均只计一次。历史匿名课堂保留原作答凭证兼容。
- 参与人数按已加入本次课堂的参与标识统计。待提交为已加入活动但尚未提交三道题的学生数。课中每题的答对比例以已提交三题的人数为分母。
- 大屏展示班级汇总。变式复测的同批比较只统计已提交变式题的会话，给出这批学生在原题及变式题分别答对的人数。一次作答用于即时教学判断。
- 写入通过同目录临时文件加原子替换完成。存档包含账户认证信息、课程关系、教师管理令牌、课堂参与标识、题目和答案，应仅由服务进程及管理员读取。单实例运行，可在停止服务后备份或归档指定课堂的六位码 JSON 文件。
- 单实例最多保存 200 场课堂，每场最多允许 256 个课堂参与者。达到上限后既有学生仍能完成课堂。普通 JSON 请求体限 256 KiB，课件及签到照片有独立上传限制。出题与课程答疑共享最多 3 个同时进行的模型请求，有密钥时每个服务进程每滚动起算的 24 小时窗口最多允许 60 次上游尝试。容量和额度耗尽会在界面返回明确提示。

## 验收与参赛材料

```bash
go test ./...
go test -race ./...
```

测试覆盖课堂建立与恢复、多人并发提交、重复提交、选项合法性、教师授权、反馈开关、推题后补交首轮、复测计分、异常写盘、演示容量、模型结果校验与示例降级。生成接口测试会启动临时回环 HTTP 服务。

教师桌面按 1440px 宽度、学生端按 390px 宽度验收。模型调用使用可控上游测试，未以学生真实照片做识别准确率评测。现场展示需再次从一个独立手机网络或可互访局域网复核真实地址，断开并恢复学生网络一次，检查保留草稿和提交状态。作品简介、3 分钟路演、90 秒操作流程和 AI 使用记录见[参赛材料](./参赛材料.md)。

前端模型与二维码脚本的源文件在 `frontend/`。仅当修改这些资源时才需执行 `npm ci` 和 `npm run build:visuals`，构建产物位于 `web/assets/`。
