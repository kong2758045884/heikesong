# 随堂三问

教师讲完一个知识点，发出基础理解、误区辨别、迁移应用三道题。学生手机匿名作答，教师看全班选项分布，选出值得讲解的错项，再用一道变式题当堂复核。《随堂三问》面向 TRAE AI 校园黑客松学习教育赛道「辅助教师教学」方向。

[在线演示](https://biology-get-genesis-third.trycloudflare.com/) · [作品简介、路演稿与演示脚本](./参赛材料.md)

演示地址使用临时 HTTPS 隧道，依赖演示电脑和隧道持续运行。

## 三分钟开课

需要 Go 1.20 或更新版本。从项目根目录执行下列命令，打开 [本机教师入口](http://localhost:8787)。前端发布资源随源码提供，Go 后端只用标准库，运行演示无需安装 Node 或填写模型密钥。

```bash
go run .
```

1. 教师载入七年级数学「一元一次方程的移项」，逐题核对题干、选项、答案、解析，设置学生能否查看反馈，再发布。
2. 手机与讲台电脑接入可互访的同一网络。手机扫码或打开大屏复制的加入链接，提交三题。可用另一部手机或独立浏览器会话作为第二名现场体验者。
3. 教师在大屏查看各题选项分布。以第二题的「移项时保留了原符号」为例，讲解为什么两边要同时加 3，核对变式题后推送。学生在原页面完成复测。
4. 查看同批复答者在原题和变式题的答对人数，然后结束活动。每场新课堂从零开始，收集到的提交才会计入大屏。

从本机打开教师入口时，服务会尽量使用物理网卡的内网地址生成二维码。多网卡机器可以指定手机实测可达的地址，例如 `PUBLIC_BASE_URL=http://192.168.1.20:8787 go run .`，将示例 IP 换成本机实际地址。开课前用现场手机打开一次加入页。校园 Wi-Fi 的客户端隔离可能阻止设备互访，这种场地可使用公网 HTTPS 部署或可互访的热点。

## 单服务部署

**Go 可执行文件。** 以下命令构建的文件内含师生界面和二维码资源，可单独拷到同架构的系统运行。设置 `DATA_DIR` 指向本项目的独立持久目录。启动时如工作目录下有 `web/index.html`，服务优先读取该份前端，方便现场调整。

```bash
go build -trimpath -o sanwen .
DATA_DIR=./data/rooms ./sanwen
```

**容器。** 将本仓库作为构建上下文。镜像只运行一个无特权 Go 进程，一个命名卷保留历次课堂。示例命令适用于本机和局域网演示。

```bash
docker build -t suitang-sanwen .
docker run --name suitang-sanwen -p 8787:8787 \
  -v suitang-sanwen-data:/data \
  -e PUBLIC_BASE_URL=http://192.168.1.20:8787 \
  suitang-sanwen
```

**评委公网入口。** 在支持 Go 进程或 Docker 的主机部署一个实例。将公网 HTTPS 域名反代到该进程，设置 `PUBLIC_BASE_URL` 为实际访问源站（例如 `https://class.example.edu`），将专属持久卷挂到 `DATA_DIR`。根路径 `/` 为教师入口，`/healthz` 为 HTTP 健康检查。以平台动态分配的 `PORT` 监听时无需设置 `ADDR`。完成部署后，用校外网络打开教师页、建课，用手机扫码并提交一份答案，确认大屏出现该提交再向评委发链接。域名示例仅作配置说明。

| 环境变量 | 作用 |
| --- | --- |
| `ADDR`、`PORT` | `ADDR` 优先，可设为 `127.0.0.1:8787` 供同机反向代理使用。默认监听所有网卡的 `PORT`，端口默认 8787。 |
| `PUBLIC_BASE_URL` | 从手机及评委网络可访问的 HTTP(S) 根地址。HTTPS 代理、容器和多网卡部署应显式设置。 |
| `DATA_DIR` | 默认 `data/rooms`，容器默认 `/data/rooms`。一个服务实例独占一个目录。 |
| `WEB_DIR` | 可选，用指定目录覆盖内置静态页面。 |
| `AI_API_KEY`、`AI_MODEL` | 由服务端读取。使用主持团队有权调用的模型及密钥。 |
| `AI_BASE_URL` | 兼容 Chat Completions 的上游 API 根地址，默认 `https://api.openai.com/v1`，服务自动追加 `/chat/completions`。 |

AI 出题仅向模型发送学科、年级、知识点和出题约束。未配置密钥、上游超时或返回题目结构不合要求时，系统返回带来源标记的数学示例，并展示示例的实际知识点。教师需审核所有待推送内容。程序对照教师确认的正确选项评分。

## 统计与数据

- 每个课堂获得独立六位加入码和教师管理令牌。学生凭浏览器生成的随机会话加入。刷新、同一会话重发相同答卷均计一次。更换浏览器或清空存储可形成新会话。
- 参与人数按已加入匿名会话统计。待提交是其中尚未提交整套三题的人数，未扫码的在册学生不在此数内。课中每题的答对比例以已提交三题的人数为分母。
- 大屏展示班级汇总。变式复测的同批比较只统计已提交变式题的会话，给出这批学生在原题及变式题分别答对的人数。一次作答用于即时教学判断。
- 写入通过同目录临时文件加原子替换完成。存档包含教师管理令牌、匿名会话标识、题目和答案，应仅由服务进程及管理员读取。单实例运行，可在停止服务后备份或归档指定课堂的六位码 JSON 文件。
- 单实例最多保存 200 场课堂，每场最多允许 256 个匿名会话。达到上限后既有学生仍能完成课堂。每个请求体限 256 KiB，模型生成最多同时处理 3 次，有密钥时每个服务进程每滚动起算的 24 小时窗口最多允许 60 次上游尝试。容量和额度耗尽会在界面返回明确提示。

## 验收与参赛材料

```bash
go test ./...
go test -race ./...
```

测试覆盖课堂建立与恢复、多人并发提交、重复提交、选项合法性、教师授权、反馈开关、推题后补交首轮、复测计分、异常写盘、演示容量、模型结果校验与示例降级。生成接口测试会启动临时回环 HTTP 服务。

教师桌面按 1440px 宽度、学生端按 390px 宽度验收。现场展示需再次从一个独立手机网络或可互访局域网复核真实地址，断开并恢复学生网络一次，检查保留草稿和提交状态。作品简介、3 分钟路演、90 秒操作流程和 AI 使用记录见[参赛材料](./参赛材料.md)。

前端模型与二维码脚本的源文件在 `frontend/`。仅当修改这些资源时才需执行 `npm ci` 和 `npm run build:visuals`，构建产物位于 `web/assets/`。
